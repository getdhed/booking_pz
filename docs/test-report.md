# Отчёт о тестировании — Лабораторная работа №2

**Тема:** тест-дизайн и проверка UC-01 «Добавление переговорной комнаты» в Booking PZ.  
**Ветка:** `lab2-test-cases`. **Проверяемая версия (commit):** _вписать перед прогоном_.  
**Исполнители (бригада из 2 человек):** _вписать_. **Дата:** _вписать_.

## 1. Цель

Проверить, что администратор может добавить новую комнату, система сохраняет и отображает корректные данные, а недопустимые значения, дублирующиеся номера и попытки без достаточных прав не приводят к созданию записи.

**Основание:** `docs/use-case-UC-01.md` и [12 ручных тест-кейсов](test-cases.md). Исходный проект — учебное приложение с имитацией ролей в URL, не с полноценной системой авторизации.

## 2. Методика

Использованы:
- классы эквивалентности: допустимые/недопустимые значения и наличие/отсутствие полей;
- граничные значения: пределы длины текста, этажей и вместимости;
- таблица решений: без роли / обычный пользователь / администратор;
- позитивные и негативные сценарии: создание, сохранение, дублирование номера.

**Важно:** внутри TC-03, TC-05, TC-06, TC-07, TC-08 несколько наборов входных данных, но каждый из них проверяет одно требование. Общий статус кейса `Passed` ставится только если все его варианты прошли.
