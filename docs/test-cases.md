# Лабораторная работа №2 — тест-кейсы UC-01 «Добавление переговорной комнаты»

**Объект тестирования:** веб-приложение Booking PZ, маршрут `GET/POST /add`.
**Основание:** `docs/use-case-UC-01.md` и текущие серверные ограничения проекта.
**Среда:** локальный сервер Node.js, PostgreSQL, браузер; для отправки некорректных значений можно использовать Postman/curl.
**Статус:** тест-кейсы подготовлены, **фактическое выполнение на развернутом приложении пока не проводилось**.

## Общие предусловия и тестовые данные

1. PostgreSQL доступна, приложение запущено через `npm start`.
2. В качестве базовых данных формы используются:
   - `name=Переговорная Тест`
   - `roomNumber=LAB2-001` (для каждого позитивного теста использовать **новый уникальный номер**, кроме теста на дубликат)
   - `location=Главный корпус`
   - `floor=2`
   - `capacity=10`
   - `description=Учебная комната`
3. Для положительных сценариев администратор открывает `http://localhost:3000/add?auth=1&role=admin`.
4. Один и тот же набор данных в разных тестах должен отличаться уникальным номером комнаты; после проверки можно удалить созданные комнаты через админский интерфейс.
5. После каждого негативного теста убедиться, что новая запись в списке не появилась.

## Пример выполнения тест-кейса TC-WEB-14

- **Предусловие:** существует работающий сервер и доступ администратора.
- **Тестовые данные:** базовый набор данных, `floor=0`.
- **Шаг 1:** отправить `POST http://localhost:3000/add?auth=1&role=admin` с типом тела `x-www-form-urlencoded`.
- **Шаг 2:** передать поля `name`, `roomNumber`, `location`, `floor`, `capacity`, `description`.
- **Шаг 3:** проверить HTTP-код и сообщение об ошибке.
- **Шаг 4:** убедиться, что запись с данным номером не появилась.
- **Ожидаемо:** `400 Bad Request`; «Этаж: требуется целое число от 1 до 100.»; запись отсутствует.
- **Фактически:** не проверено.
- **Статус:** Not Run.

## Учет результатов

Используйте:
- **Passed** — фактический результат совпадает с ожидаемым;
- **Failed** — обнаружено несоответствие;
- **Blocked** — тест невозможно провести из-за внешнего препятствия;
- **Skipped** — тест сознательно пропущен;
- **Not Run** — тест ещё не выполнялся.

При `Failed` добавьте запись о дефекте в `docs/test-report.md`, включив шаги воспроизведения, ожидаемый и фактический результат, среду и доказательства (скриншот/лог).
